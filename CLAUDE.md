## 3. Архитектура
- Autoload-синглтоны: `EventBus`, `GameManager` (state machine), `TimeManager`, `SaveManager`, `ChemistryEngine`, `AudioManager`.
- Служебный autoload `_mcp_game_helper` (плагин godot-ai) — только для редактора, в релизных сборках его быть не должно. Его вырезает сам плагин: `addons/godot_ai/export/mcp_export_plugin.gd` убирает запись из снимка настроек на время экспорта (`project.godot` на диске не меняется), в том числе при headless-экспорте. Не удалять его из `project.godot` руками — плагин вернёт. В пресетах экспорта исключать `addons/godot_ai/*`. При первой сборке (T-08) проверить, что в паке нет `_mcp_game_helper`.
- Системы общаются через сигналы `EventBus`, а не прямыми ссылками друг на друга.
- Одна сцена `CaseScene.tscn` для всех кейсов; кейс загружается из JSON.
- UI собирается из переиспользуемых сцен-компонентов (`ItemSlot`, `Zone`, `TimerLabel`).
- Пиксельная графика: базовое разрешение **640×360**, stretch mode `canvas_items`, aspect `keep`/`expand`, масштаб целочисленный, фильтр текстур `Nearest`.

## 5. Правила работы
1. Бери **одну** задачу из `TASKS.md`, сверху вниз. Не начинай следующую, пока текущая не проверена.
2. После задачи: запусти проект/тесты, обнови `PROGRESS.md` (дата, что сделано, что проверено, что сломано), отметь задачу `[x]`.
3. Для поиска по коду сначала используй `codebase-memory-mcp` (граф), а не чтение файлов целиком.
4. Не держи подключёнными лишние MCP: по умолчанию `godot-ai` + `codebase-memory`. Арт-MCP включать только в арт-сессиях.
5. Перед изменением `.tscn` вручную — проверь, нельзя ли сделать это через Godot MCP. Если правишь текстом — запусти сцену после правки.
6. Коммить маленькими шагами: `feat:`, `fix:`, `data:`, `art:`, `docs:`.
7. Если задача требует решения, которого нет в документах, — остановись и спроси, а не придумывай.
8. Арт-генерация (PixelLab, Retro Diffusion) тратит общий лимит/деньги. **Режим экономии (с 19.10.2026): пауза в генерациях до 18.11.2026** (обновление лимита). После паузы — партии больше 10 генераций только с согласия Александра; перед партией сказать, сколько и зачем; после — отчёт «потрачено / осталось». Не выходить за месячный лимит подписки (кредиты сверх лимита — только с согласия). Результаты `create_map_object` удаляются через 8 ч — сохранять в `game/assets/_incoming/` сразу.
9. Порядок запуска: сначала редактор Godot, потом `claude` (MCP `godot-ai` подключается к серверу, который поднимает плагин). Если Claude стартовал раньше — `/mcp` → godot-ai → reconnect. При обновлении godot-ai: закрыть Claude → закрыть Godot → обновить → Godot → Claude (иначе старый `attach` снова поднимет сервер старой версии).

10. **Все промпты для генераторов (PixelLab, Retro Diffusion и др.) и описания ассетов в `docs/ASSETS.md` — только на английском.** Общение с Александром — по-русски.
11. Перед любой арт-сессией прочитай раздел «Решения и уроки поиска стиля» (`docs/ART_PIPELINE.md` §3.5).
12. Ассеты: `game/assets/_incoming/` — сырьё, в git не попадает; `game/assets/pending/` — в git, уже используется в сценах, ждёт утверждения Александра; `game/assets/approved/` — утверждено. Сцены ссылаются только на `pending/` и `approved/`, никогда на `_incoming/`. После ока — перенести из `pending/` в `approved/`, отклонённое удалить.
13. `project.godot` и autoload: если `godot-ai` подключён — менять autoload через него. Если правил `project.godot` текстом при открытом редакторе — в отчёте предупредить: «нужно Reload from disk + Reload Current Project» (иначе редактор перезапишет файл своей копией).
14. **Качество важнее скорости.** Перед каждым показом Александру: открыть каждый скриншот в полном размере и пройти по каждому предмету «Чек-лист приёмки сцены» (`docs/ART_PIPELINE.md` §3.6): контакт с полом/стеной и тень, масштаб к герою (~60 px), симметрия и оси, ориентация к центру зоны, нет нагромождений, чёткость (целый масштаб, Nearest, без размытых копий), читаемость текста при 640×360 и 1280×720, свет у огня, z-порядок, анимации без дёрганий. В каждом отчёте — раздел **«Найденные недочёты»**: что нашёл сам, что исправил, что не смог. Не переходить к следующему шагу, пока чек-лист не пройден.
15. **Комнаты — по одной** (ART_PIPELINE §3.4): R1 пустая коробка → R2 крупная мебель → R3 мелочи → R4 живой мир → R5 логика; стоп и показ после каждого шага. Запуск — сначала Godot, потом Claude (п. 9); у Александра выставлен `MCP_TIMEOUT=60000` (холодный старт godot-ai ~50 с).

## 6. Химия — правила контента
- Реакции основаны на **реальной** химии и физике. Если реакция спорная — пометь `"verified": false` и спроси.
- У каждой реакции есть короткий научный факт (`science_note`) — 1–2 предложения, проверяемые.
- Реакции **абстрагированы**: в игре нет точных пропорций, температур и пошаговых методик, которые работали бы как реальная инструкция.
- **Никогда** не добавлять в игру: взрывчатые вещества и их прекурсоры, получение токсичных газов как цель, синтез наркотиков, оружие, яды. Опасные побочные продукты допустимы только как предупреждение/провал («так делать нельзя, вот почему»).
- Упрощения допустимы, ложь — нет. Если игровая условность расходится с наукой, отметь это в `science_note`.

## 7. Стиль кода
- `snake_case` для функций/переменных, `PascalCase` для классов и узлов, `UPPER_CASE` для констант.
- Один скрипт ≤ ~300 строк; больше — дели на компоненты.
- `class_name` для переиспользуемых типов. Сигналы называть в прошедшем времени: `reaction_completed`.
- Никаких `get_node("../../..")` — экспортируемые ссылки `@export` или сигналы.
