# Арт-пайплайн и промпты (v1.0)

## 1. Стиль — «живой 16-бит» (обновлено 18.10.2026)
Ориентир, выбранный Александром: `docs/reference/style_ref_pixellab_hero.png` (промо-арт PixelLab — **только как настроение**, элементы не копировать, в игру не включать).

Что делает этот стиль «не деревянным»:
| Приём | Как выглядит | Как добиваемся |
|---|---|---|
| Тёплое против холодного | фиолетово-синие тени + оранжево-розовый свет | в каждой сцене один тёплый источник (закат, свеча, факел) против холодной тени |
| Мягкие переходы | небо и горы — плавные градиенты через дизеринг, без «ступенек» | разрешаем дизеринг и 4–6 оттенков на материал |
| Насыщенно, но не кислотно | розовый, сиреневый, оливковый, ржаво-красный | никаких чистых #FF0000 / #00FF00 |
| Воздушная перспектива | дальние планы светлее и синее, ближние темнее и контрастнее | 3 плана глубины во всех фонах |
| Сказочность | слегка преувеличенные формы (высокие башни, пухлые облака) | лёгкий шарж — подходит нашему юмору |
| Детали на переднем плане | цветы, мох, блики на воде | «живинки» у края кадра |

**Это не строгая палитра Sega Genesis**, а современный «hi-bit» пиксель-арт в её духе (как Sea of Stars, Eastward). Поэтому:
| Параметр | Значение |
|---|---|
| Разрешение | 640×360 (×3 = 1920×1080) |
| Палитра проекта | ~64 цвета (собираем из утверждённых эталонов, T-26) |
| Цветов на спрайт персонажа/иконку | до ~24 |
| Цветов на фон крупного плана | до ~48 |
| Контур | тёмный цветной (не чёрный), у мелких спрайтов — сплошной, у фонов — выборочный |
| Свет | тёплый ключевой свет + холодные фиолетово-синие тени |

Для замка Дракулы ночью: базовая гамма — глубокие фиолетовые и сине-сливовые тени, тёплые оранжево-янтарные пятна свечей и факелов, лунный свет бледно-лиловый.

## 2. Размеры ассетов (v1.1 — два слоя)
**Карта (вид сверху):**
| Тип | Размер (px) | Примечание |
|---|---|---|
| Тайл | **32×32** (решение 18.10.2026; было 16×16) | TileMapLayer Godot, тайлсеты PixelLab (`tile_size` 32). Экран 640×360 = 20×11,25 тайла |
| Герой и NPC на карте | холст **64×64**, фигура ~58–63 px ≈ **2 тайла** в высоту (рост не ужимаем: граф сгорблен, разница естественная), **взрослые пропорции 1:5** (голова ≈ 1/5 роста), видны ноги | `create_character` MCP, 4 направления, ходьба + idle. **Никакого чиби** |
| Объект на карте | 16×16 – 32×32 | бочки, двери, гроб графа |

**Крупный план (верстак / добыча / осмотр):**
| Тип | Размер (px) | Примечание |
|---|---|---|
| Фон сцены | 640×360 | `create_image_pixen` (Tier 1: до 512×512 по площади) — генерируется целиком |
| Руки | ~96×64 на кисть | 3–4 позы (держит, сыплет, толчёт, бьёт киркой) |
| Иконка предмета | 32×32 | в инвентаре; в крупном плане ×2 |
| Иконки UI | 16×16 | |
| Эффекты | частицы Godot, не спрайты | искры, пар, шипение, осколки породы |

### Пропорции персонажей (решение 18.10.2026)
Александру не нравится чиби / «Funko Pop». Персонажи — **взрослые, высокие, детальные**, как в инди (Children of Morta, Sea of Stars, Stoneshard).
В каждый промпт персонажа добавлять:
```
adult character, realistic proportions, 1:5 head-to-body ratio, tall, visible legs and arms, detailed clothing folds
```
Негатив (или «avoid» в тексте):
```
chibi, big head, super-deformed, cute toy-like, funko pop, stubby limbs
```

## 3. Конвейер генерации
```
1. Промпт (шаблоны ниже) → генерация
     • PixelLab — для предметов, персонажей, анимаций (настоящая сетка)
     • Общий генератор — для концептов и фонов
2. tools/pixelize.py  → удалить фон → уменьшить фильтром Nearest до целевого размера
                      → свести к палитре проекта → PNG в assets/_incoming/
3. Aseprite (руками или через MCP) → почистить шум, контур, лишние пиксели
4. Перенос в game/assets/... + запись в docs/ASSETS.md (источник, промпт, дата)
```
Правило: одна сессия — одна группа ассетов в одном стиле (например, все минералы). Первый удачный результат сохраняется как **эталон стиля** и подаётся референсом в следующие генерации.

## 3.1 Кто что делает (решение 18.10)
| Кто | Инструмент | Что делает |
|---|---|---|
| **Claude Code** | PixelLab MCP/API, Retro Diffusion MCP, Aseprite MCP, `tools/pixelize.py` | массовое: серии иконок по эталону, тайлсеты, 4/8 направлений персонажей, сведение к палитре, спрайт-листы, импорт в Godot, запись в `docs/ASSETS.md` |
| **Александр** | Aseprite 1.3.18 + **расширение PixelLab** | арт-дирекция: грубый набросок → «Use init image» → пиксель-арт; Inpaint (закрасить чёрным только плохое место — лицо, руку — и перегенерировать); утверждение эталонов стиля |

Обмен: всё новое кладётся в `game/assets/_incoming/`, Claude проверяет размер/палитру и переносит на место.
Правило: один файл `.aseprite` не правят одновременно человек и Aseprite MCP.

Расширение PixelLab для Aseprite: нужна Aseprite **1.3.7+, не триал** (у нас 1.3.18 ✓) и аккаунт PixelLab (работает и на бесплатной пробе). Скачать на pixellab.ai/account → двойной клик по файлу → перезапустить Aseprite → разрешить доступ к файлам и websocket (для автообновлений — «full trust»). Открыть: Edit → PixelLab → Open plugin или Ctrl+Space+P.

## 3.2 Бюджет генераций на кейс (оценка 18.10.2026)
Цены PixelLab (ответ поддержки): `create_character` 4 направления = 1; `animate_character` = 1 за направление (ходьба ×4 = 4); `create_topdown_tileset` = 1–4 (обычно 3–4). Иконки/объекты — оценка 1 за штуку.

| Что (кейс «Замок графа») | Шт. | Генераций без переделок |
|---|---|---|
| Герой: создание + ходьба + idle | 1 | 1 + 4 + 4 = 9 |
| Граф: создание + idle (+ «просыпается») | 1 | ~6–9 |
| Летучая мышь: создание + полёт | 1 | ~5 |
| Тайлсеты: камень↔ковёр, камень↔пещера, пещера↔вода, стены | 4 | ~14–16 |
| Объекты карты (гроб, бочки, сундуки, двери, факелы…) | ~20 | ~20 |
| Иконки предметов | ~25 | ~25 |
| Фоны крупного плана (верстак, жила, дверь-головоломка) | 3–4 | ~10–20 |
| Руки (позы) | 4 | ~8 |
| **Итого** | | **~100–110** |
| **С переделками (×3–4)** | | **~300–450** |

Вывод: 5000/мес (Tier 2) ≈ 10+ кейсов в месяц; 2000/мес (Tier 1) ≈ 4–5 кейсов. Решение: **Tier 1** — `create_image_pixen` на Tier 1 даёт до 512×512 по площади, фоны 640×360 помещаются. Tier 2 — только при нехватке лимита. Перед стартом серии Claude называет оценку по этой таблице.

## 3.3 Цены API PixelLab в долларах (pixellab.ai/pixellab-api, 18.10.2026)
Применяются, когда месячные генерации закончились и списывается баланс кредитов. Оценки, зависят от времени GPU.
- Базовое: картинка Pixflux/Pixen/Bitforge ~$0.007–0.017; тайлсет top-down $0.008 (16px) / $0.010 (32px); объект карты $0.010; персонаж 4 направления $0.011–0.012 (48–64px); анимация персонажа v3 ~$0.013 за направление.
- Pro-инструменты: $0.08 / $0.115 / $0.15 (до 256 / 341 / 512 px) — использовать точечно (фоны, UI, сложные персонажи).
- Оценка кейса «на кредитах» без подписки: ~$5–10. Подписка Tier 1 ($12, 2000 генераций) выгоднее и даёт MCP + расширение Aseprite.

Полезные инструменты, о которых не знали: **Create UI elements (Pro)** — рамки/кнопки интерфейса; **Normal map** — карты нормалей для 2D-освещения в Godot (свечи и факелы в замке динамически освещают стены); **VFX** — спрайты эффектов (дым, искры) дополнительно к частицам; **Create character state** — состояния персонажа (граф спит / проснулся); **Image to pixel art** (Pro Flash, источник до 2048 px) — набросок или фото → пиксели.

✅ **Размер героя решён (ответ PixelLab 18.10.2026):** MCP `create_character` делает только квадрат (32×32 ок, 16×24 — только через API v2, 16–128 px, но ниже ~24 px качество грубое). ~~32×32~~ → **отменено 18.10.2026**: чиби-пропорции не нравятся. Новое решение: холст 64×64, пропорции 1:5, базовое разрешение 640×360.

## 3.4 Конвейер одной комнаты (поэтапно, с остановкой на утверждение после каждого этапа)
Почему слоями: если мебель нарисована на фоне, герой не может зайти **за** неё (Y-sort), её нельзя взять/сдвинуть/анимировать. Поэтому фон — пустая «коробка», всё остальное — отдельные спрайты.

| Этап | Что | Инструмент | Бюджет | Выход |
|---|---|---|---|---|
| **A. Коробка** | пустая комната: стены, окна, пол, потолочный край, дверь. **Без мебели** | `create_image_pixen` 640×360 | 2 | `rooms/<room>/shell_*.png` |
| **B. Масштаб и свет** | коробка + герой + тень + свет в Godot | Godot, godot-ai | 0 | скриншот |
| **C. Крупная мебель** | 5–8 предметов: кровать на подиуме, шкаф, секретер, туалетный столик, камин, ширма | `create_map_object` со style matching по коробке | 6–8 | `rooms/<room>/props_big/*.png` |
| **D. Мелкие предметы** | 15–20 интерактивных: письмо, тиара, страницы дневника, бокал, шкатулка, чулки, мишка, монеты… — спрайт в комнате + иконка 32×32 | `create_map_object` / `create_image_pixflux` с палитрой | 15–25 | `props_small/`, `icons/` |
| **E. Крупные планы** | «посмотреть»: вид из окна (слои для параллакса: небо, луна, облака, горы, озеро, летучие мыши), секретер с письмом, шкаф со скелетом | `create_image_pixen` 640×360 (+ слои) | 5–10 | `closeups/` |
| **F. Сведение** | палитра проекта (T-26), сведение всех слоёв к ней | скрипт, 0 генераций | 0 | `palette.png/.gpl` |
| **G. Жизнь** | мерцание свечей, колыхание балдахина и штор (шейдер), канарейка (анимация), пыль в лунном луче (частицы) | Godot + `animate_image` для канарейки | 1–4 | сцена |
| **H. Сборка** | сцена комнаты: коллизии, Y-sort, точки интереса, реакции на клик (код фазы 0) | Godot, godot-ai | 0 | `scenes/rooms/<room>.tscn` |

Итого на комнату ≈ 30–50 генераций начисто. Каждый этап — отдельная задача, после него стоп и показ Александру.

**Правила коробки (решения 18.10.2026, по итогам проб покоев принцессы):**
- **Большие помещения = анфилада экранов 640×360**, связанных арками/проходами. Камера не скроллит внутри экрана: при проходе через арку она плавно переезжает на соседний экран (~0,4 с). **Каждый экран — одна цельная генерация** `create_image_pixen` 640×360. Склейка панорам из частей и outpaint на Tier 1 не работают: pixen рисует кадр как законченную нишу (часто 2 отсека), инструментов outpaint/inpaint для 640×360 на Tier 1 нет.
- Камера-диорама (театральная сцена): дальняя стена и пол, стена за камерой не показывается.
- Масштаб: дверь ≈ 1,4× роста героя (герой 63 px → дверь ~88–90 px). В промпте: «the door is small, about one quarter of the image height».
- Дверь не на наружной стене с окнами: окна — на наружной стене, дверь — на внутренней/боковой.
- Все экраны одной анфилады начинаются с одинакового префикса промпта (материалы, свет, линия пола, правила декора), меняется только описание экрана.
- Декор симметричный и намеренный: один бант по центру над каждым окном, ровные одинаковые гирлянды между колоннами; ничего на полу; паутина только в верхних углах.
- Анимируемые детали (паутина, шторы, огонь, пыль) — отдельными спрайтами/частицами (этап G), не на фоне.

**Гибридный подход (решение 18.10.2026, эксперимент `hybrid_bedroom`):**
- **Коробка комнаты** = одна пустая генерация `create_image_pixen` 640×360 с объёмом: фронтальная задняя стена, короткие боковые стены, пол с глубиной, край свода. Без окон, дверей, арок, мебели и декора, ровный мягкий свет.
- **Архитектура** (окна, арки-проходы, колонны, двери) = общий набор на весь замок, спрайты с прозрачным фоном, фронтально, ровный свет без свечения; ставится на фронтальную заднюю стену коробки.
- **Вид из окна** — отдельный слой за окнами (небо, луна, силуэты; позже анимация облаков/луны).
- **Мебель и мелочи** — отдельные спрайты (этапы C–D).
- **Свет и атмосфера** — светом Godot (CanvasModulate + PointLight2D), не в спрайтах.
- Исключение: будуар (`approved/room_princess_boudoir.png`) остаётся цельной картинкой.

**Порядок работы с комнатой (с 18.10.2026, заменяет чистую сборку — подробности и причины в §3.5):**
1. Эскиз из деталей: коробка + архитектура + крупный декор по нашей раскладке (сцена Godot → кадр 640×360 без героя).
2. Перерисовка: `create_image_pro` 640×360, эскиз — `reference_images` (раскладка), `approved/room_princess_boudoir.png` — `style_image`. 2 варианта, ≈ 25 генераций за вариант.
3. Живые слои поверх выбранного варианта: небо за стеклом окон (маска), огонь факелов (частицы + PointLight2D), качающаяся паутина, колыхание штор, пульсация лунных лучей, триггеры проходов. Всё, что анимируется или трогается героем, — отдельным слоем, не запекать.
4. Края кадра: сторона перехода в соседний экран — открытая (без боковой стены); глухие боковые стены — только у крайних комнат анфилады.
5. Декор генерировать в ракурсе поверхности, к которой он крепится (§3.5); у каждого предмета — понятная роль.
6. Перед любой арт-сессией — прочитать §3.5.

**Порядок для мебели и крупных предметов (с 18.10.2026, тест — кровать принцессы):**
1. Генерация: `create_image_pro` с прозрачным фоном, `style_image` = сама комната (её approved-картинка), не будуар. Холст ≤ 170 px по большей стороне → 4 кандидата за ~15 генераций.
2. Ракурс камеры комнаты: в промпте «seen strictly from the front, symmetrical, flat front view slightly from above, no isometric angle» — без этого модель рисует изометрию 3/4.
3. Масштаб по герою (~60 px): кровать ~140–170 px в ширину, двери/проходы 1,4–1,5 роста.
4. Контактная тень на пол — отдельный спрайт (ступенчатая альфа, не плавная), под предметом.
5. Y-sort: предмет — узел в `Props` (y_sort_enabled), origin = линия «подошвы» на полу; герой — на том же уровне сортировки. Коллизия `StaticBody2D` только по «подошве» (площадь пола под предметом).
6. Хотспот: `Area2D` со скриптом `components/hotspot.gd` и `Label`-подсказкой («Осмотреть»).
7. Огонь и свет предмета (свеча, ночник) — частицы + `PointLight2D` поверх, в спрайте без пламени.

## 3.5 Решения и уроки поиска стиля (октябрь 2026)

**Решения**
- Комнаты = анфилада экранов 640×360, связанных проходами; камера переезжает между экранами (~0,4 с). Будуар (`approved/room_princess_boudoir.png`) — цельная картинка и эталон стиля всех комнат.
- Основной способ делать комнату: эскиз из деталей (раскладка наша) → перерисовка `create_image_pro` с будуаром как образцом стиля (цельность) → живые слои поверх. Цена 25–50 генераций на комнату.
- Живые слои: небо за окнами (луна, облака), огонь факелов (частицы + свет), качающаяся паутина, колыхание штор, пульсация лунных лучей. Всё, что анимируется или трогается героем, — отдельным слоем, не запекать.
- Края кадра: сторона перехода — открытая (без боковой стены); глухие боковые стены — только у крайних комнат анфилады.
- Ракурс декора = ракурс поверхности крепления: задняя стена — фронтально чуть сверху; колонна/угол — 3/4 влево/вправо; потолок — чуть снизу. У навесного предмета — мягкая тень на поверхность.
- У каждого декоративного предмета — понятная роль. Шторы обрамляют окна и не закрывают вид. Банты — только объёмные и в нужном ракурсе, иначе в резерв.
- Факелы — основной свет покоев (с анимацией). Бра и свечи — резерв для других комнат.
- Паутина: 5–7 разных, привязаны к реальным углам архитектуры, полупрозрачные, покачиваются (шейдер `cobweb_sway`).
- Двери/проходы ≈ 1,4–1,5 роста героя, стоят на полу; дверь не на стене с окнами.
- Герой: поза 1802 (3/4, рука опущена; `approved/hero_pose_34.png`), тапки цвета v7 a, эмоция «чешет затылок» — отдельная анимация. Фронтальные нейтральные позы (1701–1703) отклонены: герой не стоит «истуканом» лицом к камере.
- Мебель и интерактивные предметы — всегда отдельные спрайты.
- Варианты для ревью — отдельными файлами, не склейкой.

**Уроки (что не работает)**
- Склейка панорамы из кусков 640×360: pixen рисует каждый кадр как законченную нишу (диптих), стыки не сходятся.
- Слово "alcove" модель читает как театральную ложу/сцену с балюстрадой.
- "bedroom" в промпте пустой коробки → дорисовывает кровать, свечи, банты. Работает "bare empty stone room shell".
- Детали, просто положенные на фон, выглядят наклейками (нет откосов, теней, единого света) — поэтому перерисовка.
- Уменьшение пиксель-арта масштабом мылит — генерировать сразу в нужном размере.
- Фото-референсы чужого арта в генератор не подавать.
- Слова "unlit" / "no flame" pixen игнорирует у факелов и бра; плющ и ступени у арок появляются, даже если они в Avoid, — чистить скриптом или формулировать «clean smooth cut stone».
- v3-поворот персонажа вшивает позу референса во все направления (рука на затылке осталась во всех ракурсах) — референс должен быть в нужной базовой позе.
- PixelLab рисует каждый кадр анимации заново → лицо и глаза «плывут» (кажется, что герой моргает и бегает глазами). После генерации анимаций всегда фиксировать голову+лицо из одного лучшего кадра каждого направления скриптом (перенос со смещением bob); скрипт — `game/assets/_incoming/hero_anim/v34/clean/hero_cleanup.py`.
- Мелкие эстетические правки (форма уха, блики) — быстрее руками в Aseprite (спрайт-листы `.aseprite` лежат рядом с `.png`); механические (перекраска, копирование, мусорные пиксели, вырезка стёкол) — скриптами.
- Шаблонные анимации ходьбы (`walk`, `walking-6-frames`) у вида спереди/сзади дают переминание на месте; v3 с описанием шага («clear alternating steps, each leg lifts and moves forward») — настоящий шаг.
- Слои вида из окна pixen почти всегда рисует с рамой/шторами по краям — брать центральную часть; светящиеся окна в башнях («домики с огоньком») закрашивать.
- Маски стекла — только 1-битные (alpha 0 или 255), никаких полупрозрачных краёв в пиксель-арте. Переплёт окна (импосты, розетка, трейсери) — отдельный слой поверх вида из окна, а не вырезать его вместе со стеклом; порядок: небо → переплёт → стена. Скрипт: заливка от точек внутри каждого проёма, ограниченная колоннами рамы; светлые блики рамы, касающиеся тёмного контура, не трогать.
- Передние колонны в запечённом фоне перекрывают героя: вырезать колонну отдельным спрайтом (`room_*_pillar.png`) с z_index поверх героя + коллизия по основанию.
- При фиксации головы в анимации шея двигается вместе с головой: иначе «дышащий» воротник наезжает на подбородок («второй подбородок»). Idle лучше собирать из одного кадра: голова и шея неподвижны, плечи/грудь +1 px, ~1 цикл за 1,6 с (`tools/anim_cleanup.py`, `BREATH_SETS`).
- Навесные/свисающие части предмета, по которым герой может пройти (одеяло на полу, ковёр), — отдельным нижним слоем без коллизии.
- Мелкие дефекты перерисовки (пятно кладки, заплатка) — `inpaint_image_pro_flash` только этого участка по маске (кроп ≤ 256 px, ≈ 6 генераций), а не перегенерация комнаты.

**Цены для планирования** (Tier 1, генерации): `create_image_pixen` = 1; `edit_image_pro_flash` 64×64 ≈ 5; `create_image_pro` 640×360 = 25 за вариант; `create_character` v3 от референса = 1 (4 направления); `animate_character` template = 1 за направление, v3 64 px = 1 за направление; `create_topdown_tileset` standard ≈ 4. Фактические расходы — в `docs/ASSETS.md`.
Для покоев принцессы: `<room>` = `princess_chamber`, путь `game/assets/_incoming/rooms/princess_chamber/`.
